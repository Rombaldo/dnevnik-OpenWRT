# Мой дневник (домашняя страница для Дневник.ру)

Показывает домашку (с файлами), оценки и расписание из веб-версии Дневник.ру в простом виде.
Живёт на домашнем роутере и работает круглосуточно по домашней Wi-Fi. Mac включать не нужно.

## Где открыть
**http://192.168.10.1:8765** на телефоне и планшете (в той же домашней Wi-Fi). Адрес роутера постоянный.
Чтобы был значок на главном экране: Safari на iPhone → «Поделиться» → «На экран “Домой”»;
Яндекс Браузер на Android → меню ⋮ → «Добавить на главный экран».
QR-код с адресом: `./dev.sh qr http://192.168.10.1:8765`.

Данные обновляются раз в 20 минут с 6:00 до 23:00. Кнопка «Обновить» делает это сразу.

## Раз в две недели: войти заново
Вход через Госуслуги живёт примерно 2–4 недели. Когда страница напишет «Нужно войти в Дневник.ру заново»:
1. Включить Mac, двойной щелчок по **Войти.command**.
2. В открывшемся окне нажать «Войти через Госуслуги» и войти. Окно закроется само.
3. Вход сам передастся на роутер и данные обновятся. Mac можно выключать.

## Как это устроено
- **Mac нужен только для входа.** Госуслуги проходят в браузере, и это единственное, что делает Mac (`fetcher.py login`).
- **Роутер** (OpenWrt) сам ходит на dnevnik.ru раз в 20 минут (`sync.py`, без браузера) и отдаёт страницу
  на порту 8765 (`uhttpd`). Веб-интерфейс самого роутера на порту 80 не затронут.
- **Вложения к домашке** не скачиваются и не хранятся: на странице ссылка, файл открывается прямо с сервера Дневник.ру.
- **На флеш-память роутера** пишется только то, что изменилось (история дней) и вход не чаще раза в 6 часов.
  Данные для страницы лежат в оперативной памяти и после перезагрузки роутера собираются заново сами.

### Если что-то не так
- Страница не открывается: проверьте, что телефон в домашней Wi-Fi. Состояние роутера: `./dev.sh router`.
- Данные «старые»: смотрите отметку «Обновлено …» вверху страницы. Журнал обновлений: `./dev.sh router`.
- Переустановить на роутер: `./dev.sh deploy` (с передачей входа: `./dev.sh deploy login`).
- Убрать с роутера:
  ```
  ssh -i data/router_key root@192.168.10.1 '/etc/init.d/dnevnik stop; /etc/init.d/dnevnik disable; rm -f /etc/init.d/dnevnik; rm -rf /root/dnevnik; sed -i "/dnevnik/d" /etc/crontabs/root; /etc/init.d/cron restart'
  ```
  Затем на странице роутера (System → Administration → SSH-Keys) можно удалить ключ `dnevnik-claude`.

## Установка на роутер из GitHub (приватный репозиторий)
Репозиторий приватный, поэтому роутеру нужен токен только на чтение. Он лежит на роутере в `/root/.dnevnik-token` (права 600).

**Один раз создать токен** (в браузере, под вашим аккаунтом GitHub):
Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token.
- Repository access: **Only select repositories** → выбрать `dnevnik-home`.
- Permissions → Repository permissions → **Contents: Read-only** (больше ничего).
- Срок: например, 1 год. Скопировать токен (он показывается один раз).

**Положить токен на роутер** (токен вводится скрыто и нигде не печатается): `./dev.sh token`

**Установить на роутер** (на самом роутере по SSH, или с Mac одной командой `./dev.sh update`):
```
wget -qO- --header="Authorization: Bearer $(cat /root/.dnevnik-token)" \
  https://raw.githubusercontent.com/Rombaldo/dnevnik-home/main/router/install.sh | sh
```
Скрипт сам доустановит Python-модули, скачает программу, включит службу и расписание. Вход (cookie) и данные не трогает.
Обновить позже: `sh /root/dnevnik/router/install.sh` (или `./dev.sh update`). Конкретная версия: `REF=v0.5.0 sh /root/dnevnik/router/install.sh`.
Убрать: `sh /root/dnevnik/router/uninstall.sh` (с `--keep` данные остаются).
После первой установки останется войти в Дневник.ру: `./dev.sh login` на Mac.

**Перед первой отправкой на GitHub:** `./dev.sh secrets` проверяет файлы и всю историю git на ключи, токены, cookie входа и личные данные.

## Безопасность: как устроен вход
- **Госуслуги проходит только человек** в окне браузера на Mac. Пароль и коды в программу не попадают.
- От входа сохраняются **только cookie Дневник.ру** (`data/session.json`, права 600, папка `data/` закрыта 700).
  Cookie Госуслуг, Яндекса и прочих сайтов отбрасываются при сохранении и при чтении.
- Cookie отправляются только на `dnevnik.ru` по HTTPS, проверка сертификатов всегда включена. На сервер файлов, на чужие
  адреса и по обычному HTTP они не уходят (есть тесты).
- На роутер вход попадает по SSH-ключу (`data/router_key`, он даёт доступ к роутеру: никому не отправлять), файл на роутере закрыт 600.
- В git не попадают `data/`, `config.json`, ключи и токены: `.gitignore`, хук перед коммитом и `./dev.sh secrets`.
- Тексты с сайта (темы, домашка, названия файлов) выводятся на страницу экранированными, это проверяет тест.
- Страница на роутере открыта всем устройствам домашней сети без пароля. Из интернета её не видно.

## Запасной вариант: запуск на Mac
`Запустить.command` запускает ту же страницу на Mac (`http://<адрес-Mac>:8765`). Нужен, если роутер недоступен.
Работает, пока Mac включён.

## Заметки
- Программа только читает дневник, ничего не отмечает и не отправляет.
- Галочки «сделано» хранятся только в браузере устройства.
- Папка `data/` содержит сохранённый вход (`session.json`), ключ от роутера (`router_key`) и личные данные.
  Никому не отправлять и не выкладывать (в git она не попадает).
- Страница доступна всем устройствам вашей домашней сети. Из интернета она не видна (у вас нет публичного IP).
  Доступ из мобильного интернета пока не настроен.

## Для разработки
Все команды через `./dev.sh`:

| Команда | Что делает |
|---|---|
| `./dev.sh setup` | создаёт окружение и ставит зависимости (один раз) |
| `./dev.sh demo` | страница на **выдуманных данных**: http://localhost:8766, входить в Дневник.ру не нужно |
| `./dev.sh test` | запускает все тесты (в том числе проверку страницы в настоящем браузере) |
| `./dev.sh run` | запускает на Mac с настоящими данными |
| `./dev.sh login` | вход через Госуслуги и передача входа на роутер |
| `./dev.sh deploy [login]` | выложить программу на роутер |
| `./dev.sh router` | журнал обновлений и файлы данных на роутере |
| `./dev.sh sync` | одно обновление данных на Mac |
| `./dev.sh token` | положить токен GitHub (только чтение) на роутер |
| `./dev.sh update` | обновить роутер до последней версии из GitHub |
| `./dev.sh secrets` | проверить файлы и всю историю git на секреты |
| `./dev.sh qr [адрес]` | QR-код с адресом страницы |

Устройство кода:
- `core.py` — разбор данных и обновление по HTTP, только стандартная библиотека (работает на роутере).
- `sync.py` — запуск одного обновления; `fetcher.py` — вход через браузер (Playwright) на Mac.
- `server.py` — сервер для Mac и демо; `web/` — страница; `router/` — установка на роутер; `dev/sample.py` — выдуманные данные.

### Версии
- Номер версии в файле `VERSION`, список изменений в `CHANGELOG.md`. Номер виден внизу страницы.
- Перед коммитом: `./dev.sh test`. Для релиза: поднять `VERSION`, дописать `CHANGELOG.md`, коммит, тег `git tag vX.Y.Z`,
  `./dev.sh deploy` (выложить на роутер).
- Тест проверяет, что версия из `VERSION` есть в `CHANGELOG.md`.

### Личные данные в git не попадают
`data/` (вход, ключ, оценки, домашка), `config.json` (имя), `.venv/` и QR-код добавлены в `.gitignore`.
Сверх этого хук `.githooks/pre-commit` блокирует коммит, если туда всё же попали такие файлы или cookie входа
(включается командой `git config core.hooksPath .githooks`, в этой копии уже включён).
Образец настроек: `config.example.json`. В демо-режиме и тестах только выдуманные данные из `dev/sample.py`.
