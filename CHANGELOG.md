# История версий

Формат: номер версии, дата, что изменилось. Версию меняем в файле `VERSION`.

## 0.21.0 — 2026-11-13
- **«Устройства и входы» в LuCI.** Список устройств, подключённых к уведомлениям (имя, тип, служба, когда подключено, сбои, кнопка «Отключить»), список «кто открывал дневник» (тип устройства, откуда, последний заход) и **журнал входов по паролю семьи** с неверными попытками
  (подряд идущие с одного устройства сливаются в «×N»; слишком частые попытки, код 429, не пишутся). Кнопки «Обновить список» и «Очистить журнал» (с подтверждением).
- **Устройство определяется по браузеру** (iPhone · Safari, Android (SM-X710) · Chrome, Windows · Edge, Samsung Internet, Яндекс Браузер, Huawei Browser и другие), откуда: из дома, из интернета (Funnel приходит с самого роутера), через Tailscale. **Адреса, строки браузера и пароли в журнал не пишутся.**
  Устройство опознаётся по случайной метке в cookie `dnevnik_dev` (пароля в ней нет); «последний заход» хранится в оперативной памяти и обновляется не чаще раза в 5 минут, журнал входов пишется только при входе (флеш-память не изнашивается).
- **Имя устройства** при включении уведомлений (⚙ → «Уведомления»), его можно менять; видно в списке в LuCI.
- «Проверить всё» предупреждает, если за сутки было 10 и больше неверных попыток входа (кто-то подбирает пароль).
- Старые подписки на уведомления получают название по сохранённой строке браузера; адрес подписки с секретным токеном устройства в список не попадает.
- Тесты: определение устройства (14 браузеров, мусор, обрезанные строки, разметка в строке браузера), откуда, журнал (слияние, ограничение, битые файлы), настоящие CGI (метка выдаётся один раз, 429 не пишется, без пароля не пишется, Secure на https, сбой записи не мешает входу),
  «последний заход», имя и список подписок, методы LuCI и карточка (пустые списки, предупреждения, подтверждения, чужой текст не выполняется), поле имени на странице.

## 0.20.0 — 2026-11-13
- **Уведомления на телефон (веб-пуш).** О новой оценке, новой домашке, отмене и изменении уроков, пропусках и опоздании. Работают и при закрытой странице, на Android (Chrome) и iPhone (Safari, iOS 16.4+, страница на экране «Домой»),
  без приложений. ⚙ → «Уведомления»: включить на этом устройстве, выбрать типы событий, тихие часы (утром сводка), «Проверить уведомление», выключить; раздел «Что нового» с последними событиями.
  Настройки у каждого устройства свои.
- **Приватность.** Текст шифруется для самого телефона (RFC 8291, aes128gcm; подпись отправителя VAPID по RFC 8292), Google и Apple прочитать его не могут. Шифрование проверено по примеру из стандарта байт в байт и независимой расшифровкой в тестах.
  Подписки принимаются только от Google, Apple, Mozilla и Microsoft (защита от обращений к чужим адресам); подписка, настройки и проверка защищены паролем семьи; не чаще одной проверки в 5 секунд; не больше 20 устройств.
- **Как работает.** `notify.py` после каждого обновления с сайта сравнивает данные с прошлым разом и находит события (первое обновление только запоминает, не шлёт; много событий сводятся в одно; домашка и расписание только на сегодня и позже),
  `push.py` шифрует и отправляет (повторяет при сбоях сети, убирает умершие подписки, держит очередь на тихие часы), `router/push.cgi` принимает подписки, `web/sw.js` показывает уведомление.
  Сбой уведомлений обновление данных не ломает. Задержка до 20 минут (интервал обновления).
- **Установка модуля.** `router/push.sh` (или `install.sh --push`) ставит `python3-cryptography` (около 4 МБ), проверяет место и создаёт ключ отправителя. «Проверить всё» показывает пункт «Уведомления» (устройства, результат последней отправки).
- Тесты: определение событий для каждого типа (первое обновление, повторы, потоки, отмена и перенос, пропуски), шифрование и подпись, подписки и настройки, тихие часы, отправка с подставной службой пушей (удалённые и временно недоступные устройства), CGI и сервер,
  установка модуля, карточка на странице с подставными API браузера (включение, отказ, ошибки, настройки, iPhone и http-адрес) и сервис-воркер.

## 0.19.0 — 2026-11-12
- **Установка от нуля до работающего дневника.** Новый раздел README «Быстрый старт»: что понадобится, два способа (с компьютера без терминала и по SSH),
  дальнейшие шаги и таблица «что видите → что делать».
- **«Проверить всё» (`router/doctor.py`).** Проходит по всей системе и говорит, что работает, а что нет и что делать: место, страница, выдача данных (и что данные
  не лежат в открытой папке), имя dnevnik.lan, расписание, вход в Дневник.ру и свежесть данных, связь с dnevnik.ru, пароль семьи (красным, если страница в интернете без пароля),
  Tailscale, Funnel, прокси. Режимы: полный список, `--summary` (установщик показывает его в конце), `--json` (для LuCI), `--report` (текст для просьбы о помощи без паролей,
  логинов, имён и адресов). Ничего не меняет. Кнопка «Проверить всё» есть в LuCI.
- **Доступ из интернета одной командой (`router/remote.sh`, ключ `install.sh --remote`).** Ставит Tailscale, помогает войти в аккаунт, включает Funnel, печатает адрес.
  Безопасен для повторных запусков (сделанное пропускает), без пароля семьи в интернет не выставляет, перед установкой проверяет место и честно останавливается, если его мало,
  при необходимости говорит, что нажать в браузере («Connect device», «Enable Funnel»), и возвращает код 2, пока вы этого не сделали.
- **Прокси для Tailscale: то, что реально помогло.** Если Tailscale входит в аккаунт, но не оживает (`NeedsLogin`), а на роутере есть прокси (Clash/SSClash, порт 7890), скрипт сам
  добавляет в `/etc/init.d/tailscale` строку `HTTPS_PROXY=… HTTP_PROXY=… NO_PROXY=…` (между метками `# >>> dnevnik-proxy` и `# <<< dnevnik-proxy`, исходник сохраняется
  как `.bak-dnevnik`) и повторяет вход. Вручную: `remote.sh proxy on [адрес:порт]` и `remote.sh proxy off`. Старую ручную правку распознаёт и переводит в меченый блок.
  Причина и последствия описаны в README (раздел «Прокси для Tailscale»).
- **LuCI: «Доступ из интернета и проверка».** Адрес для семьи, состояние Tailscale и прокси, команда для включения, кнопка «Проверить всё» и «Приглашение для семьи»
  (готовый текст с адресом и инструкцией, как добавить страницу на экран «Домой»; пароля в нём нет). Методы `remote_info` и `doctor` (только чтение).
- **Установка с компьютера для человека без SSH (`tools/setup_computer.py`, `setup-windows.bat`, `Установить-на-роутер.command`).** Задаёт вопросы простыми словами, по SSH ставит
  программу, задаёт пароль семьи (переменными окружения, а не аргументами: в списке процессов роутера его нет), включает доступ из интернета (сама открывает браузер там, где нужно
  нажать), помогает войти в Дневник.ру и печатает адреса. `password.py set-env` задаёт пароль из переменных окружения.
- Тесты: сценарии `remote.sh` с подставными `tailscale`, `apk`, `df`, `netstat` (чистая установка, нет места, нет пароля, вход через прокси, Funnel не разрешён, повторный запуск,
  миграция старой ручной правки, плохой адрес прокси), `doctor` (каждый вердикт, отчёт без личных данных, ничего не пишет), LuCI и установка с компьютера
  (кавычки в пароле, пароль не в аргументах, сценарий не «съедает» себя, разбор вывода, весь разговор).
- Найдено тестами: `sed -i` в BusyBox и BSD работает по-разному, правка файла службы переписана без него.
- **`AGENTS.md` и `CLAUDE.md`: установка с помощью ИИ-агента.** Подробная инструкция для любого агента (Claude Code, Codex, Cursor, Aider, DeepSeek-харнесс, чат): правила безопасности (пароли не
  просить и в чат не принимать, разрешение перед выходом в интернет, резервная копия, честность), два режима (есть терминал или агент-проводник), восемь шагов с проверками, таблица «что делать»,
  справочник команд и кодов выхода. Есть тест, что все упомянутые файлы, команды и строка прокси существуют и совпадают с настоящими скриптами, и что в инструкции нет личных данных.
- **Честная совместимость.** README: таблица версий OpenWrt (проверено 25.12; 21.02–24.10 должно работать, не проверялось; старше не поддерживается) и компьютеров (Windows 10/11, Mac, Linux;
  Windows 7/8 только с оговорками). Программа установки с компьютера сама проверяет `ssh` и версию Python и по-русски подсказывает выход (Git for Windows, Python 3.8, PuTTY); «Проверить всё» сообщает
  о версии OpenWrt.

## 0.17.0 — 2026-11-12
- **Пароль семьи может быть любым, даже из одного символа.** Раньше требовалось не меньше 8 символов. Это сознательный выбор хозяина: короткий пароль
  подобрать легко, особенно если страница открыта из интернета (защита от перебора только замедляет: после 5 неверных попыток подряд ждать 30 секунд,
  потом дольше, до 15 минут). На странице, в LuCI и по SSH об этом напоминает подсказка рядом с полем, но запрета нет. Пустой пароль и пробелы по-прежнему нельзя.
- Подсказка к очень короткому паролю (меньше 3 символов): отклоняется только подсказка, совпадающая с паролем (иначе из-за одной буквы не проходила бы почти любая).
  К паролям от 3 символов правило прежнее: сам пароль в подсказке нельзя.

## 0.16.0 — 2026-11-12
- **Карточка оценки.** Нажмите на любую оценку («Последние оценки» и кружки в «По предметам»): откроется окно, как на сайте дневника. В нём предмет,
  за что поставлена («Ответ на уроке, 11 ноября»), учитель, тема урока, сама оценка и **средний балл по предмету**. Средний балл берётся тот же,
  что показывает сайт за этот период; если сайт его не дал, считается по всем оценкам дневника. Стрелка ↑ или ↓ показывает, подняла ли эта оценка
  средний балл или опустила (у самой первой оценки по предмету стрелки нет). Закрывается кнопкой, крестиком, Esc и нажатием на тёмный фон;
  оценки открываются и с клавиатуры (Enter, пробел). Рейтинг и «одноклассники» с сайта не показываются: это платные функции.
- **Посещаемость теперь внизу экрана «Оценки»** (раньше была самой первой): и в «Сейчас», и в периодах на вкладке «Годы и итоги».
- **Сколько дней был в школе, а не только уроков.** В карточке посещаемости новая строка: «Дней в школе: 38 из 42 дней». Учебные дни берутся
  из расписания, будущие не считаются; день считается пропущенным, если пропущены все его уроки, а дни с частью пропущенных уроков показаны
  отдельно («из них неполных: N»). Строка есть и в карточке «за год». За прошлые годы сайт расписание не отдаёт, поэтому там число не показывается:
  лучше ничего, чем неточное.
- Тесты: порядок блоков, подсчёт дней на заранее известных пропусках, склонение «дня/дней», карточка оценки (содержимое, стрелки, средний балл
  с сайта и свой, закрытие, клавиатура, чужой текст на странице не выполняется, маленький экран).

## 0.15.0 — 2026-11-12
- **Пароль семьи в веб-интерфейсе роутера (LuCI).** «Службы → Дневник → Пароль семьи»: задать, сменить, отключить. Старый пароль знать не нужно:
  в LuCI входит только хозяин роутера, так что так же сбрасывается и забытый пароль (все устройства семьи после этого входят заново, блокировка
  перебора снимается). Состояние пароля и дата его смены видны на странице. Серверная часть: методы `family_set` и `family_off` (только запись).
- **Подсказка к паролю** (по желанию, до 100 символов). Показывается на экране входа вместе со справкой «Забыли пароль?». Её видит каждый, кто откроет
  страницу, поэтому подсказка с самим паролем не принимается (ни на странице, ни в LuCI, ни по SSH). Подсказку можно менять отдельно от пароля
  (на странице: нужен текущий пароль). `password.py set 'пароль' 'подсказка'`.
- Экран входа объясняет, как задать новый пароль, и честно говорит, что со страницы дневника его сбросить нельзя.
- Тесты: подсказка (очистка, длина, отказ при совпадении с паролем), методы LuCI и права на них, блок на странице LuCI, экран входа и настройки на странице.

## 0.14.0 — 2026-11-12
- **Пароль для семьи.** Один общий пароль на страницу: ⚙ → «Пароль для семьи». Пока он не задан, всё работает как раньше (домашняя сеть).
  Когда задан, без него не отдаётся ничего: ни данные дневника, ни кнопки «Обновить» и «Выйти из аккаунта», ни форма входа в Дневник.ру.
  Устройство вводит пароль один раз и запоминает его на 180 дней (cookie `dnevnik_auth` с подписью HMAC, `HttpOnly`, `SameSite=Lax`,
  `Secure` при https). Пароль хранится только как хеш PBKDF2 с солью (`data/auth.json`, права 600). Смена и отключение требуют и cookie,
  и текущий пароль; после смены все остальные устройства выходят. Перебор тормозится: после 5 неудач подряд ждать 30 секунд, потом дольше
  (до 15 минут). Забытый пароль сбрасывается по SSH: `python3 /root/dnevnik/router/password.py set 'новый' | off | status`.
  Если файл `auth.json` испорчен, страница остаётся закрытой, а не открытой.
- **Данные больше не лежат в открытой папке веб-сервера.** Раньше `data.json` и `offline.html` (с теми же данными) отдавались любой прямой ссылкой.
  Теперь данные лежат в `/tmp/dnevnik-private`, а страница берёт их через `cgi-bin/data`, который проверяет пароль. Старые файлы удаляются при запуске службы.
  На роутере «сохранённой копии» `offline.html` больше нет (она остаётся только в версии для Mac).
- `cgi-bin/refresh` переписан на Python (то же поведение: не чаще раза в 2 минуты) и тоже проверяет пароль. Вход через компьютер
  (`tools/login_computer.py`) понимает закрытую паролем страницу и не пытается проверить загрузку.
- Новые файлы: `auth.py`, `router/auth.cgi`, `router/data.cgi`, `router/password.py`. Установщик и `deploy.sh` их выкладывают.
- Тесты: модуль пароля, все CGI на роутере (с паролем и без), сервер для Mac, раскладка файлов и сама страница в браузере.

## 0.13.0 — 2026-11-12
- **Вход через Госуслуги на любом компьютере, одной командой.** `python3 tools/login_computer.py` (на Windows двойной щелчок по
  `login-windows.bat`). Скрипт сам готовит окружение (Playwright и браузер, один раз), открывает окно для входа через Госуслуги и передаёт
  вход на роутер по SSH (спросит пароль роутера), потом ждёт, пока дневник загрузится. Роутер проверяет присланное (только cookie dnevnik.ru
  и цифровые номера ученика и школы), пишет файлы с правами 600 и ничего не меняет, если вход выглядит неправильно. Ключ `--forget` стирает
  вход с чужого компьютера, `--no-browser` повторяет передачу без нового входа, `--router` и `--identity` для другого адреса и SSH-ключа.
- В README подробная пошаговая инструкция для Windows, Mac и Linux с разбором частых ошибок.

## 0.12.0 — 2026-11-12

  адрес), кнопки «Открыть дневник», «Обновить сейчас», «Проверить новую версию» (и «Обновить до …»), «Выйти из аккаунта» (с теми же двумя
